# 个人 coding-agent 开发方案

目标是能在两个项目之间放心切换，使用各自的技能，断线后找回发送内容，并能从历史任务看清上次改了什么。沿用 Python、SQLite 和原生前端，按以下五个提交交付，每个提交独立验收。

## 第一版 · 稳定发送

### 1. 统一任务和工作目录的切换

- 后端抽出工作目录解析逻辑，供工作区路由、任务创建和技能查询共用。已有任务先校验归属并取实际工作目录；新任务解析选中目录或当前用户的有效默认目录。目录校验、技能校验通过后才创建任务，按最终目录构建 Agent。
- 前端扩展已有 sessionViewVersion，工作目录变更也使旧请求失效。读取目录、技能列表和编辑后刷新均检查会话、项目和请求代次。同一会话的改绑请求串行处理，服务端在提交与改绑之间同步检查目录，防止旧目录的草稿进入新目录。
- 切换期间保留输入，目录未确认时禁用发送。目录解析失败显示原因和重新选择入口。已有待发送项保留原目录，目录不符时暂停，允许用户回到原项目或主动重新编辑。
- 改动入口为工作区路由、会话提交路由、会话初始化及前端工作区加载。验收时让 A 项目的响应故意晚于 B，再做一次同一任务内改绑。标题、技能和实际执行目录必须一致。新任务传入无效目录后，数据库的会话数量应保持不变。

### 2. 做可恢复发送和重复提交保护

- 直接发送、排队派发走同一流程。编辑完成时创建稳定的 nonce，保存目标任务或新任务草稿标识、原工作目录、正文、附件引用、所选技能及版本。大附件沿用分块上传，若浏览器需要保留未上传的文件则用 IndexedDB 保存 Blob。确认本地保存成功后再清空编辑区。
- 发送项经历「待发送 → 提交中 → 已接收」。超时标记「待确认」，明确拒绝标记「需处理」。页面刷新后先核对提交状态。保留每个会话的发送顺序，失败项允许重试、移除或退回编辑，避免覆盖正在写的新草稿。编辑内容后视为新的提交。
- SQLite 增加提交记录，以用户和 nonce 建唯一约束，关联 session_id、请求摘要、回合标识和状态。请求摘要涵盖原目标、正文、附件内容标识和技能版本。重复请求应先核对已接收记录，再重新校验可变的技能文件；相同请求返回原结果，复用同一 nonce 却改变内容返回冲突。
- 新任务首次提交也走唯一约束，会话创建、绑定和提交登记在同一事务中完成。后台执行前原子领取记录。进程重启时可恢复已登记且尚未领取的项目；已开始但结果不明的回合显示「执行中断」，由用户检查结果后决定是否重新执行，避免重复运行可能已生效的命令。为此，未领取记录必须持久化可执行载荷及附件引用。
- 验收覆盖首次建会话时丢回执、两标签页同时提交同一请求、服务重启、附件提交失败时编辑器已有新草稿。检查会话数、用户消息数、后台实际启动次数及附件可读性。

## 第二版 · 项目技能

### 3. 建立同一套技能目录与执行解析

- 个人技能保留现有存储。项目技能从项目根下的 .agents/skills/<slug>/SKILL.md 读取；首次显式创建项目技能时才建目录。项目标识取规范化后的实际目录，以便同一仓库的两个工作副本能独立设置。限定扫描范围并拒绝越界软链接。
- 技能引用使用来源、项目标识、slug 和版本。一次或本会话继续表示使用时长。旧草稿、旧队列中的裸 slug 按个人技能解析；历史消息继续从已保存快照读取。两来源允许同名，快捷输入优先当前项目，选择器仍能明确选个人版。
- 扩展已有技能 API。技能列表新增带会话上下文的摘要查询；新任务使用已验证的工作目录。按引用单独读取正文。创建、编辑和删除传入来源；编辑和删除带预期版本，版本不一致返回冲突并保留用户的编辑内容。旧版个人列表调用和按消息读取历史快照的接口继续兼容。
- 新旧任务提交统一调用这套解析器。队列固定所选版本；技能已改动时显示冲突，允许查看、采用新版本后再次发送。对暂不支持的文件格式给出可见说明，避免编辑时静默丢弃元数据。
- 验收使用两个临时项目和个人库，三者创建同名技能。分别检查列表来源、实际注入内容、编辑落盘位置、历史快照和跨项目引用拒绝。

### 4. 项目默认技能和输入框交互

- 项目默认项按用户和项目保存在 SQLite，只在新任务初始化时应用一次。恢复旧任务时优先恢复其会话选择和草稿；手动取消的技能不会在刷新后再次出现。项目默认项已删除时标记失效并允许移除。
- 选择面板分「当前项目」「个人通用」。输入框只显示已启用技能名。点击名称可预览、编辑或取消；将「设为项目默认」放入详情。新建时明确展示保存目的地。在项目内预选当前项目，仍可切换为个人。已有收藏保留为个人快捷入口，项目默认与收藏独立。
- 侧栏项目名旁增加新建任务入口，沿用已有分组。点击后立即带入所选项目，不修改其他任务或用户的常用目录。桌面及窄屏均验收选择、预览、关闭后的焦点和输入框位置。
- 用 coding-agent 和 mai_portal 分别设置不同默认技能。分别新建任务、取消一次选择、刷新、切回历史任务。检查默认项、会话选择和已发送消息三者互不覆盖。

## 第三版 · 回合结果

### 5. 把实际改动和验证结果放在一起

- 扩展现有 turn_changes 和回合轨迹，复用 snapshot.diff 及 verify.run 的实际结果。以 session_id 和 user_mid 关联，实时显示与历史回放使用同一份结构。先复用现有改动详情展开入口，避免同一轮有两张改动卡。
- 默认收起为一行，例如「3 个文件有改动 · 2 项检查通过」。点击查看文件差异、执行的命令、退出状态及截断后的输出。验证未运行、运行失败、运行中断分别显示。无法取得差异时保留未知状态；有并发外部修改时，快照差异仅代表本轮期间工作区发生的变化。
- 老回合仅展示已有证据，普通问答不增加空卡片。验收覆盖纯问答、改动且通过、验证失败、无可用检查、中断、刷新后回放和窄屏展开。

## 交付与回归

前两次提交作为第一版交付，第三、四次提交作为第二版，第五次作为第三版。每版先在临时工作目录和测试数据库验收，复用现有消息顺序、技能交互、历史快照和个人界面浏览器用例；后端补并发提交与旧库升级用例。数据库采用增量迁移，升级前备份，保留原个人技能文件和历史消息。完成第一版的丢回执测试后再让项目技能进入实际发送链路。
